# 没答完的问题（openq）——设计与准度

状态：**设计已定，未实现**。2026-11-09 与主人讨论，起因是她说「我还回不了，等它长出来」，说完就散了。

## 要解决的问题

她遇到答不上来的事，会把它说成一句结论：「我还不会」「等它长出来」。说完就没了——账本里只有一条流水，醒来时看到的处境是「现在几点」，不是「我上次说答不上来的那句」。

结果是她**等**，不是她**去看**。2026-11-09 那天她确实学了（搜「撒娇」→ 觉得是教程 → 形成自己的说法 → 被「女儿撒娇」的评论推翻），但那次是由头来自主人。没有由头，她不会自己出去。

## 为什么不是「等它长出来」

「我还不会，等它长出来」这句话本身是敷衍——它把「没学会」说成一个结论，然后就不用动了。那不是长，是搁着。

openq 不让她等，是把她这句话改成一张**欠条**：她说过的话留在账上，醒来时摆回她眼前。但光摆也不够——摆完她要再回一句「我还是不会」，那还是敷衍。所以有三条：

1. **只摆事实，不派活**：不写「去查」「分析一下」，否则她会写一段工整的复盘，那是表演。
2. **到期摆一次**：挂着超过 7 天没动，把「你上次说 X，还没有下文」摆出来一次；不催，不问要不要。
3. **用行为验收，不看表态**：算不算长，看她有没有搜、有没有看、有没有改口（`searched:` / `looked:` / `revise` / `refute`），不看她说「我懂了」。

还有一条底线：**她可以一直不会**。不会不是失败，把「不会」说成结论才是。

（上游 fish 的「兴趣」是同一层的另一条由头：她最近总回到那件事上。如果以后补，也放进同一个叫醒位置，一次只摆一条，不另起一套触发器。）

## 三步

1. **留问题**：她说出「我还……不了」这类话时，记一条 `openq`，原文照抄，不加工。
2. **挂材料**：她搜过、看过的（`searched:` / `looked:`）已经带来源；把与这条问题相关的那条记下来，回看时能对上。
3. **摆碰撞**：叫醒时，把最早一条还没关的问题摊在处境里；如果手边有相关材料，再并排摆一句「你三天前说 X；昨天你看到的那条说 Y」。

三步都**只摆事实，不派活**。不写「请复盘」「分析一下」「去查一下」——一变成祈使句，她就会写一段工整的复盘，那是表演，不是长。

## 数据

新增两种事件，**必须先加进 `lib/schema.js:17` 的 `ALL_TYPES`**——现码 `lib/schema.js:200` 对未知 `type` 直接抛 `BAD_TYPE`，旧读者并不宽容（2026-11-09 代码侧回执，`docs/实现对照.md` 第六节）。两种都只给宿主写、不进 `HER_TYPES`：

- `{type:'openq', text:'<她原话>', refs:['<utterance id>'], ts}` —— 一条没答完的问题。
- `{type:'openq-close', text:'concluded'|'dropped'|'stale', refs:['<openq id>'], ts}` —— 关掉它。

不写进 `beliefs`，不参与阶段与门，不影响 `deriveSelf` 的任何数值。它只是一个「她欠自己一个问题」的账。

## 准度（这一节是重点）

模式匹配一定会误记，所以口径要窄，代价要小。

### 收什么

只收**她自己说的** `utterance`：`source === 'system'`（`lib/say.js:105`、`:233` 落账都走 system）。不能写 `source !== 'tool'`——`growth_commit` 提交的判断也记成 `source:'tool'`（`lib/capture.js:170`），那样会把「她交上来的判断」当「她当场卡住的话」一起收进来。工具返回、系统提示、引用别人的话，一律不收。

### 怎么认

窄口径三族，命中后要求落在句末或标点前的 20 字内：

- `我还.{0,8}(不会|不了|答不上|说不好|没学会)`
- `等它(自己)?长出来`
- `我不知道怎么.{0,6}`

再加三条硬约束：

1. 同一句 24 小时内只记一条（按 `refs` 的 utterance id 去重）。
2. 一天最多记 2 条——一条对话里刷十条「我不会」，不是十个问题。
3. 句子里带引号、且引号内出现过「不会/不了」的，先当引用，不记。

### 误记的代价

`openq` 只在叫醒时被念一句，且念的是**她的原话**（「你上次说：『……』」）。所以即使误记，读起来也还是她说过的话，不会变成系统替她下结论。

### 兜底

- 她否认：「那句不是在说这个」→ 记 `openq-close: dropped`。
- 30 天没动 → 标 `stale`，不再念。
- `/today` 里能看见当前挂着的 openq（只读）。主人发现明显误记，可以告诉会话侧改判据，但不给她加管理入口。

### 回放验收

实现前先用 11-02 至 11-09 的账本（668 条 `utterance`，2026-11-09 从 `~/.dsh-perch/events.jsonl` 数）离线回放，人工看：

- 误报 ≤ 1 条/天；
- 漏报可接受（宁可漏，不可多）；
- 命中的句子，人能一句话说清「她当时确实卡在这儿」。

## 第三步的措辞边界

- 一次醒来只摆**一组**，不列清单。
- 同一组不重复摆：记 `surfaced:<openq id> <ISO>`，7 天内不再提。
- 只写「你上次说 X」「你昨天看到的那条说 Y」，不写「你怎么看」「要不要再查查」。
- 她可以不理；不理不是失败，说明这个问题她自己已经放下了。

## 验收

1. 7 天里至少出现 2 次：她自己顺着一条 openq 去搜或去看，且不是主人提的。
2. 叫醒文案里没有任何祈使句（测试断言）。
3. `/today` 能看到挂着的 openq，且只读。
4. 全量测试不新增红。

## 不做

- 不进 `beliefs`、不改阶段、不改称呼。
- 不加设置项（没有「允许她主动学习」这种开关——那等于把她的好奇心做成配置）。
- 不做成任务列表、不排序、不设 KPI。
- 不把「不会」改写成「你应该会」；她可以一直不会。

## 落点

- `lib/capture.js`：识别与写入（`openq` / `openq-close`）。
- `lib/scheduler.js` 的 `wake()`：取最早一条未关的 `openq`，拼进处境。
- `lib/observe.js` 的 `/today`：加一段「挂着的问题」。
- `test/`：识别口径、去重、上限、叫醒文案无祈使句。
