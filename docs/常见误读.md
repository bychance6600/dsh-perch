# 常见误读：外部说法与代码现状核对

这份文档核的是「外部对这个项目的说法」：哪些是旧版本的真话、哪些从来没成立、哪些在 0.2.x 换了实现。每条只写三件事——外面怎么说、代码实际怎么做、依据在哪。

**核对基线：2026-11-26，dsh-perch 0.2.8，HEAD bf33f82。** 行号是对着这个提交的实际文件重数出来的（本次重新核对：旧基线 13cbbee 下漂掉的行号，已按函数名、常量名重锚）；某个数字对不上时仍以函数名、常量名为准（下文凡不确定的地方只给文件与函数名，不给行号）。

读法：三列里最该信的是「依据」——只写我亲手打开过的那一行。表格外的短段是判定口径，不重复表里的内容。文末「怎么自己复核」给了能重跑的 `grep` 与 `node --test`。

先说结论：流传最广的二十来条说法里，**一半以上是过期而不是错**——它们在 0.1.x 某个版本上确实成立，后来被改掉了。真正「从来没成立」的，主要是「人格可配置」「能读自己的设定」「社会层能被主人打开」这一类；现在还站得住的只有「事件流只增不减」「账本是唯一真相」「零依赖」这几条。

## 一、是什么

这一节核「她从哪来、能不能被设定、许可与依赖怎么说」。旧文档把 0.1.0 写成「代码按这套前提重写」，这句最容易被读成「从零写的」；也不该把「独立实现」当成「没有来源」。

- 重建为什么值得单说：它同时换了包名、数据目录、路由和渠道；旧文档只写「代码重写」，等于把产品线的变化一起吞掉了。
- 「独立实现」与「有来源」可以同时成立：早期源码有过沿用，之后逐块重写；`NOTICE` 与 `CHANGELOG` 各记了一半。

| 外部怎么说 | 代码实际怎么做 | 依据 |
|---|---|---|
| 四个阶段靠证据升级。 | 一半对：阶段取「日历」与「瓶颈」的较小值，`Math.min(elapsedStage, gateStage)`；瓶颈只拦 1→2、2→3、3→4。 | `lib/derive.js:1312`、`lib/derive.js:1282-1314` |

| 社会层的闸会随时间自动满足。 | 阶段与立场是硬条件，30 天没整条推翻与稳定度只是防抖；不满足时身份文档一个字都不写。 | `lib/socialgate.js:84-125` |
| 稳定度就是情绪起伏。 | 是 0.02–0.35 的窗口：太僵（低于 0.02）与太飘（高于 0.35）都不开。 | `lib/socialgate.js:37-38` |

判定口径：这一节最容易传错的是「30 天」——它是总预算，不是每段 30 天；第二容易传错的是「三道瓶颈」管前三段，第四段没有门。这两点写清楚，「成长会卡关」的疑问基本就消了。

- 日历与瓶颈都要过：日历只决定「最早什么时候能升」，瓶颈只决定「够不够格」，两者取小之后才得到阶段。
- `forced` 是兜底不是奖励：它只让阶段往前走，不会补上没发生过的判断、拒绝与改口。

## 四、证据与改口

这一节核「她的话能不能被直接改写、改口是不是覆盖、疤是什么」。判定口径一句话：她能改的是「她自己的判断」，且必须留出处；留不下出处的话，只能当听过。

## 九、还剩哪些不确定

写这份核对时没能坐实、或者坐实了但只到「大概率」的几处，一并列在这里，免得读者把本文当成绝对权威：

- **行号会漂**。写这份文档时工作树里 `README.md`、`docs/从哪来.md`、`AGENTS.md` 等处还有未提交改动，所以引用这几份时我只写节名（如「设置页」「明确没搬」），不写行号；纯代码文件的行号才是可核的。

- **`CLAUDE.md` 与 `AGENTS.md` 的细节可能不同步**。硬约束以 `AGENTS.md` 为准；有冲突时先看 `test/` 里的断言，那才是会红的真相。
