# 换桥

> 给「明天桥突然连不上」的人。目标：不改插件一行代码，换一只 OneBot 11 桥。

## 一、桥是什么，插件管到哪

桥是一个**独立进程**：它登录 QQ、维持连接，把 QQ 的收发翻译成 OneBot 11。插件只当 OneBot 11 客户端，连它的 WebSocket。

真正收发只用到三个标准 action：

- `get_login_info`：连上后确认自己是谁；
- `send_group_msg` / `send_private_msg`：往群里或私聊发话。

另外每 30 秒发一次 `get_status` 当心跳，也属于 OneBot 11 标准。**不用任何桥的扩展 action**，所以换桥不用改插件。

方向别弄反：桥要开「正向 WS / WebSocket 服务端」，插件连过去。插件没有「反向 WS」入口；桥如果只能当客户端往外连，它和本插件接不上。

## 二、可换的桥

| 桥 | 怎么开正向 WS | 默认端口 |
| --- | --- | --- |
| **SnowLuma** | 默认就开正向 WS。WebUI 在 `http://localhost:5099`，令牌默认随机生成，去 WebUI 或 `config/onebot.json` 抄 | 3001 |
| **NapCat** | WebUI `http://127.0.0.1:6099` → 网络配置 → 新建 → WebSocket 服务端。默认监听 `0.0.0.0`，令牌默认空 | 3001 |
| **LLOneBot** | QQ NT 的 LLOneBot 设置里开「OneBot 11 / 正向 WS」 | 3001 |
| **Lagrange.OneBot** | 正向 WS 默认没开。在 `appsettings.json` 的 `Implementations` 里加 `ForwardWebSocket`，官方示例 8081 | 8081 |
| **go-cqhttp** | 已停更，不建议新装。老配置在 `config.yml` 的 `servers` 下加 `- ws:` | 文档示例 8080，社区常见 6700，以生成的配置为准 |

选一个就行。新装优先 SnowLuma 或 NapCat；已经在用 Lagrange 的，把它的正向 WS 打开即可。NapCat / LLOneBot 如果监听 `0.0.0.0`，一定设访问令牌，别把没鉴权的 OneBot 端口放到公网。

## 三、换桥五步

**1. 停旧桥。** 退出旧桥进程，确认端口已经空出来：

```bash
# macOS / Linux
lsof -nP -iTCP:3001 -sTCP:LISTEN

# Windows
netstat -ano | findstr :3001
```

两只桥同时登同一个 QQ 会互踢，也会抢同一个端口；插件连到谁看运气。

**2. 新桥开正向 WS。** 照上表。桥和插件在同一台机器时，host 填 `127.0.0.1` 最省事；要跨机器或容器，才用 `0.0.0.0` 并处理防火墙、端口映射和令牌。

**3. 设置页填地址与令牌。** 设置 →「渠道」→ QQ 卡。卡名还叫「QQ（SnowLuma）」，NapCat / LLOneBot 也填这里，不用改卡名。

- 「桥地址」填 `ws://127.0.0.1:<端口>`；
- 「访问令牌」填桥那边设的那个，没设就留空；
- 「桥的程序路径」可留空；填了才能用「启动桥」。

保存只写配置。渠道层是插件启动时读配置的，**改完地址或令牌要重启 DSH**；只刷新设置页不会重连。

**4. 点「测一下通不通」。** 它只做一次 TCP 握手，不通会直接说。**通了也只代表端口有人，不代表令牌对、账号在线、OneBot 握手成功**——绿的之后还要做第四节四件事。

**5. 群里 @ 一次。** 先发一句不 @ 的，确认流水收得到；再 @ 她一句，确认点名。她回不回还受阶段、静默和群白名单限制；不回不等于 @ 没认出来。

## 四、换完验四件事

| 验什么 | 怎么做 | 看到什么算过 |
| --- | --- | --- |
| 登录信息拿得到 | 看桥自己的日志；设置页 →「数据」→ 运行日志导出，搜 `get_login_info` | 桥日志显示账号已登录；插件日志没有 `get_login_info 失败`，也没有 `rejected unauthorized` |
| 群消息收得到 | 在群里发一句**不 @** 的 | QQ 卡的「最近的流水」里出现这句 |
| @ 认得出 | 在群里 @ 她一句 | 日志里不该出现「只留背景」；出现就是这句话没被当成点名 |
| 发得出去 | 让她回一句，或用 QQ 卡里「以我的名义发」发一句 | QQ 群里收到；流水里有发出的记录 |

四条里最容易被「测一下通不通」骗过去的是第一条：端口通，不等于令牌对。令牌错时插件日志会反复出现 `rejected unauthorized`。

## 五、已知差异，先别当成插件坏了

- **消息格式可能是数组，也可能是 CQ 码字符串。** 插件两种都认；如果 @ 认不出，先看桥的 `messagePostFormat` / `post_format` 是不是 `array` 或 `string`，第三种格式大概率不认。
- **自己发的消息会回推。** 插件按 `self_id` 丢掉。挡不住时先看 `get_login_info` 有没有成功——self_id 空的时候，它认不出哪条是自己发的。
- **重连可能补推历史。** 插件按 `message_id` 去重；如果还看到旧话，先确认不是两只桥同时在推。
- **SnowLuma 重启可能换令牌。** 这个仓库的实测是：桥一重启，就要把新令牌填回设置页并重启 DSH，否则日志每 60 秒一条 `rejected unauthorized`。
- **令牌走查询参数。** 本插件把令牌放在 `ws://…?access_token=…`；只认 `Authorization: Bearer` 的桥可能连不上，换桥或改用能认查询参数的桥。

## 六、边界

插件里永远不接平台协议：不登录、不扫码、不实现 QQ 协议。桥挂了就换桥，不要把协议搬进插件（`AGENTS.md` §7）。
