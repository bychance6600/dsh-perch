# 从哪来：骨架、皮与这一版的取舍

这个项目不是从零写的。它的优点几乎都能指出来源；写这份文档，是为了不把别人的东西说成自己的，也不把旧版的包袱当成血统。

一共三次版本、两条血脉：

| | 是什么 | 留下了什么 |
| --- | --- | --- |
| [ssamurias/dsh-fish](https://github.com/ssamurias/dsh-fish) `0.8.5` | 一条白纸养起的鱼：人格只能从事件里长出来，会自己刷 B 站，没有任何人设配置 | **骨**：事件流、四阶段与三道瓶颈、立场、拒绝与疤、记忆的显著性与遗忘、B 站浏览、零依赖 |
| [Britneycode/dsh-fish-soul](https://github.com/Britneycode/dsh-fish-soul) `0.12.0` | 一个能替你说话的 QQ / B 站 / 抖音 小号：人格可配、按人记忆、有作息 | **皮的思路**：按人记忆的字段、每聊一句的流水、出站筛选；实现是重写的 |
| [bychance6600/dsh-fish-river](https://github.com/bychance6600/dsh-fish-river) | 把上面两个接成同一个人：骨 + 皮，多平台 | **整合经验与试错**：双通道成长、社会层四道闸、渠道适配、世界书、观测台；也是这一版要修的东西 |
| 本仓库 `dsh-perch` | 从 river 重置：收窄入口，保留骨与双通道 | **这一版的取舍**：渠道只剩 QQ + DSH、材料改成报纸 + 搜索、设置页按她的一天、身体独立成 `dsh-roost-pet` |

## 一、为什么重置

river 把「她能在哪儿说话」铺得很开：QQ、B 站私信、抖音私信。用了几天，问题不在能不能跑，而在**入口太多**——每一个入口都要一套登录、风控、去重、可见性判断；而真正让她长的，仍然只有两处：你和她的对话，以及她自己看见的东西。

材料层也有同样的毛病。river 的做法是每天醒来把 B 站、抖音推荐的几条端到她面前；她自己的说法是「像报纸一样递到我手里，这不是我挑的」。东西没错，但只有「递」，没有「挑」。

所以重置不是推翻，是**收窄**：

- 「她是谁」的入口只留两条：**你和她说话**，**她自己看见的东西**。
- 「她在哪儿说话」只留两处：**DSH 会话**、**QQ**。
- 材料从「只有报纸」变成「**报纸 + 她自己搜**」：报纸照递，搜索的词由她定，两边分开记账。

## 二、逐项：优点与出处

| 优点 | 来自 | 说明 |
| --- | --- | --- |
| 人格只能长，不能被设定 | dsh-fish 的立项前提 | 没有任何性格/人设输入口；四条黑名单写进代码，不靠提示词 |
| 单一事件流、只追加 | dsh-fish | `events.jsonl` 是唯一真相；天、阶段、判断都可重算，忘掉是降召回而不是删行 |
| 四个阶段 + 三道瓶颈 | dsh-fish | 门靠行为（写过判断、拒绝过、改过口），不靠打分 |
| 立场、拒绝、疤 | dsh-fish 0.8.x | 立场在四阶段之后才出现；拒绝与疤各自有事件形态 |
| 记忆的显著性、折叠与 90 天退档 | dsh-fish 0.8.x，后续修补被逐条移植 | 详见内部文档库 `dsh-perch-plan` 的 `docs/历史/父项移植表.md`（不公开） |
| B 站报纸、抽帧、评论只读 | dsh-fish | 抽帧与看画面一路沿用，roost 只改了动作窗口 |
| 按人记忆（`people.json`）、每会话流水（`journal.json`） | soul 的字段设计，river 实现 | 群友不逐个建档案；印象由渠道层写，不是她自己写 |
| 出站筛选、可见性、私聊泄漏检测 | soul 的思路 | 进站 `sanitizeForeign`、出站 `screenOutgoing` + `looksLikePrivateLeak` |
| 双通道成长：宪法层进判断，社会层永不进 | **river 原创** | 社会层要过四道闸、上限 30%、开闸只能她自己按 `social_open` |
| 世界书是事实，不是人格 | dsh-fish 后期 / river 保留 | 只进「你知道的事」，不改阶段、不进判断 |
| 设置页按「她的一天」排 | **roost** | 今天/状态/成长/住所/社会/上网/渠道/插件/原理/数据/反馈；今天页只读 |
| 身体不是人格 | **roost** | `dsh-roost-pet` 只显示五档与动作，不生成台词、不替她开口；素材来自 dsh-pet（MIT 代码 / CC BY-NC-SA 素材） |
| 材料层能自己挑 | **roost** | river 只有报纸；这一版加了搜索，并把「递来的 / 你搜的」分开记账 |
| 渠道收窄到 QQ + DSH | **roost** | river 有三个渠道；这一版删掉 B 站私信、抖音私信，抖音只留只读材料 |
| 零依赖 | dsh-fish 铁律 | 三个依赖字段永远是 `{}`；HTTP、签名、解压都用内置 |

一句话：**骨是 dsh-fish 的，皮的思路是 soul 的，双通道与渠道实现是 river 的，重置的取舍是这一版的。** 这一版真正新增的只有三样：收窄、可选的搜索、可选的身体。

## 三、明确没搬、也不打算搬的

| 没搬 | 为什么 |
| --- | --- |
| 人格模板、角色卡编辑 | 那是「你能配出一个她」，与本项目的前提直接冲突 |
| 好感度 / 亲密度数字 | 违反四条黑名单之一：她不给人打分 |
| BM25 + 向量检索 | 向量要 embedding 服务，等于破掉零依赖与「数据只在本地」 |
| `gateway.js`（约 1000 行） | 单角色聊天机器人的骨架，与「她的事件」模型不兼容，搬过来会长出第二个大脑 |
| 出门 / 请神、导入别人养过的那一位、桌面通知、自更新 | river 后期已删；只在设计文档里留了接回来的接口 |
| 评论区发言、领养人验证 | 写的那一半收进社会层，等她自己开闸；读评论保留 |
