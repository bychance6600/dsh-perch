## 一、已拍板的决定（别再翻）

## 二、阶段

### P0 性能与预算（不碰记忆逻辑，可先做）

1. `tools/bench.mjs`：造 1 千 / 1 万 / 5 万条合成账本，各测 `deriveSelf` 与 `searchEvents`；超预算退出码非 0。
2. 快照：账本 ≥5 万条时，把 `deriveSelf` 结果与事件偏移存 `~/.dsh-perch/derive-snapshot.json`，之后从快照往后放。
3. 日志轮转：>5MB 归档，留 3 份。
4. 数据页加三行：账本条数 / 上次重放耗时 / 磁盘占用。
5. 上下文统计：每轮记注入字符数，落一行日志（不上屏）。

**验收**：1 万条重放 < 700ms；5 万条走快照后 < 300ms；CI 有 bench 步骤；日志不再无限长。

**已收（2026-11-12）**：五项全做完。`6821158` 性能与日志/数据页/注入字符数；`ec1db05` 5 万条快照；`fe986b7` 指纹补成长日。实测 1 万条 373ms、5 万条第二次读 227ms（快照命中，冷启 6.9s 只付一次）；基线 1391 / 1381 / 9 / 1；CI 两个 node 版本都跑 bench。

### P1 改口链（M2）

`supersededBy` / `supersedes` 派生字段；被取代的判断默认不进 `searchEvents`，`includeSuperseded: true` 才查；图谱画「原话 → 改口 → 现话」。

**验收**：改口一次后，活跃召回只剩新判断；审计查询能看到旧判断与链；图谱上能连出来。

### P2 三因子召回（M1）

recency / importance / relevance；疤 +2 加在归一化前的 importance 上（上限 10）；单候选记 1。
开关 `recall.mode = 'literal' | 'ranked'`。

**验收**：30 条真实 query 对照；`ranked` 与 `literal` 可一键切；p95 < 20ms。

> **暂缓（2026-11-12 定）**
>
> 暂缓的原因：这条的验收必须落在她**真的账本**上（「换了公式之后，她记不记得以前能记起的事」在沙箱里自证不了），而真账本里有私聊原文，不能进公开仓库当 fixture。P3 要**替换** P2 的 `relevance` 公式，先做 P2 再被 P3 顶掉，等于返工。
>
> 重开时按这个顺序，别重做已经定过的判断：
> 1. **先 P3，再回 P2**。P3 定了 relevance 用 BM25，P2 只负责在它上面叠 recency 与 importance 两因子——先做 P2 会白写一遍 Dice 的归一化。
> 2. 已经定死、不用再讨论的三条：疤 `+2` 加在**归一化前的 importance**（上限 10）；单候选记 1，不许当成高匹配；开关 `recall.mode` 默认 `literal`，`ranked` 只在新版本里手动开。
> 3. 验收数据放在仓库外（`~/.dsh-perch-samples/`），只提交脱敏结论，不提交原文。
> 4. 别把「记不记得」做成可调参数——一旦能调，就会有人调到「像记得」为止。

### P3 同义词 + BM25（M3）

`lib/search-index.js`；`relevance` 用 BM25 **替换** Dice，不叠加；同义词表 60 对。

**验收**：单独 30 条 query 对照（「不开心」→「难过」这条必须过）；索引失效键 `事件数:最后 id`。

### P4 线索召回（M5）

`person` / `from` / `to` / `about` 四个参数；只传同 session 内 person 匹配的 heard；过滤为空退回词面。

**验收**：按人翻能同时翻到她自己的话与听到的话（`router.js:395` 会写 person）；跨 session 不串人。

### P5 记忆链接（M4）

独立缓存、懒计算、键绑账本长度；`recall.links` 开关；召回 1 跳扩散权重 0.5。

**验收**：derive 耗时不变；首次 < 2s、命中 < 5ms；关掉开关结果与 P2 一致。

### P6 图谱重设计（最后做，先调研）

- 调研：现有图谱是 2D 伪 3D 散点，维度已经不够（改口链、链接、按人、按时间）。先看 3 种可视化方案（力导向 3D / 时间轴 + 聚类 / 矩阵），选一种再动手。
- 合并入口：**「今天页」做成图谱页的一个标签**（今天 / 图谱 / 印象），侧栏只留一项；今天页仍只读。
- 维度：改口链、链接、按人、按时间、按状态各一种视图，不要全塞一张图。

**验收**：调研报告先出；合并后侧栏一项能到三处；今天页数据与 P1 的改口数一致。

### P7 收尾

`CHANGELOG.md`、`README.md`（不写「语义记忆」）、`docs/实现对照.md`、`PROGRESS.md`、tag `v0.2.0`、Release；市场 yml 的描述不动。

### P8 迁入经历（只迁经历，不迁人设）

目标是：别的项目/工作区养过的人想用 roost 时，能带着「发生过的事」过来，而不是带着一张人设卡。

1. 来源优先级（据 `docs/调研-养成市场.md`：能导出的只有「聊天原文 + 一张卡」，派生状态没有可移植表示）：
   - ① **SillyTavern `.jsonl`**（生态事实标准，一行一条 `JSON.stringify`；Artemis 已有读它的先例）——先做这个；
   - ② DSH 工作区会话（我们自己的生态）；
   - ③ 纯文本聊天记录（兜底，用户自己贴）。
   - 角色卡只用来拿「名字」与「世界书里的事实」，**不读性格描述与开场白**。

2. `tools/import-dsh.mjs`（DSH 工作区会话）
   - 位置：`~/.dsh/sessions/<工作区>/<会话id>/session.v4.jsonl.zstd`；zstd 多帧，Node ≥22.15 的 `zlib.zstdDecompressSync` 逐帧解（按 `28 b5 2f fd` 切帧）。
   - 只取 `user/message`（→ `heard`）与 `assistant/message`（→ `utterance`，只保留 `content[].type==='text'`，丢 `reasoning`/`tool-call`）；`system/message`、`tool/call`、`tool/result` 一律不导。
   - 文本过 `lib/guard.js` 的 `stripScaffold`；只有工具调用、没有正文的回合整条丢。
   - 时间用记录里的 `time`（毫秒）；按 `(time, sha1(text))` 去重，冲突留最早；每条导入事件带 `source: <项目>:<原消息 id>`（照 NextTavern 的来源指针）。
   - 必须显式指定来源：工作区 + 会话白名单或时间段，默认一个都不导。
3. 干跑报告：将导入 N 条 / 跳过 M 条（工具、系统、空回合）/ 拦下 K 条（像设定或脚手架）/ 去重 D 条；用户确认后才写。
4. 名字可以带（她叫什么由主人决定），**性格描述、开场白、好感度分、固定台词一律不带**。
5. 对用户的说明必须写在最显眼处：「你能带走的是你们之间发生过的事，带不走同一个人。她会读过那些事，然后自己决定怎么理解——可能像，也可能不像。」

验收：干跑报告字段齐全；同一会话导两次结果一致（幂等）；被 `system/message` 包裹的人设不进账；导入后 `deriveSelf` 不报错、阶段从第 1 阶段重新开始。

## 四、渠道补丁：QQ 图片（2026-11-12 主人点名，排在 P7 之后）

背景：她一早在 `HER_TOOLS` 里就有 `read_image`（`lib/restrict.js:88` 专门写了理由：`bili_watch` 与抖音抽帧都只是落路径，看见要靠它），但 QQ 这条渠道从没把图递进去过——`msg.images` 现在只用于合并、判空和「（只发了图，没写字）」占位（`lib/channels/router.js:509/557/219`）。桌面上放张图问她是啥，她看得见；QQ 里发给她，她看不见。

### P9-1 入站：QQ 图 → 她能看

1. `lib/channels/qq.js` 的 `readBody()` 已经把图段的 `data.url` 收进 `images`（`:573-577`）；在这一步之后加下载：落到 `~/.dsh-perch/media/qq/<sha1(url) 前 16 位>.<ext>`。
2. 上限：每条消息最多 2 张、单张 ≤10MB、下载超时 8 秒；失败只记日志，**不影响文字递送**，也不替她报错。
3. 递进上下文的方式照抄抖音（`lib/douyinlook.js:340`）：正文后另起一行「（图在 `<path>`，想看自己 `read_image`）」；正文为空时，「（只发了图，没写字）」后面接这一行。
4. 安全：只认桥给的 URL；跨域/内网地址（`127.`、`10.`、`192.168.`、`localhost`）一律不下载。

验收：入站图能落盘且路径出现在她上下文里；下载失败时文字照常递；关掉渠道/不在白名单时不下载（白名单判定在下载之前，别为没听见的群浪费流量）。

### P9-2 出站：她 → QQ 发图

1. `lib/channels/qq.js` 的 `send()` 加 `images`：本地绝对路径 → `file://<path>`（NapCat/SnowLuma 都认），桥不支持时退回 `base64://`。
2. `lib/channels/router.js` 的发送调用（`:729` 附近）把 `images` 传下去；出站仍先过 `screenOutgoing`（图不拦，字照拦）。
3. 上限：每条最多 2 张、单张 ≤5MB、只认 `png/jpg/webp/gif`；超限丢图不丢字，日志记一行。
4. 来源：她的工具产物（`bili_watch` 抽帧、故事板）与主人明确让她发的文件；**不加「随手发图」的自由**——发什么由她判断，但路径必须来自工具产出或主人给的。

验收：本地图发出后群里能看到；图超限时文字照发；`guard` 拦字时整条不发（图也不发）；测试三条（拼段、超限、路径不存在）。

### P9-3 不做（写在这里，防止以后又翻）

- 语音：要 silk 编码 + ffmpeg，收益低、风险高（占用与打包），不做。
- 表情/贴图：face id 表要跟着 QQ 版本维护，不做。
- 主动在群里接话：属于行为层不是通道层，且与封号风险直接挂钩，等真机跑过再定。
- 引用回复（`reply` 段）：单独一件小事，若 P9 做了顺手带上；不单独排期。
