# 建屋方案（0.1.0 定稿）

2026-11-07。草稿里按 river 的 757 行 `home.js` 写的分支已经作废，以这份为准。

这份文档只回答一件事：**一个人装好 dsh-roost、第一次启动时，她住在哪、怎么被建出来、重启后为什么不会多出一间空屋子。** 它不解释人格怎么长，也不解释 QQ 怎么连；那些在 `AGENTS.md` 和 `docs/约定清单.md` 里。

## 一、要解决的四件事

1. **建工作区**：侧栏里得有一个能看见她的地方，不能让人先自己建 profile，也不能只给一个带 token 的地址。
2. **建会话**：工作区下面挂一条专属会话，她和主人的话都发生在那里。
3. **幂等记账**：重启、崩溃、宿主索引延迟，都不能让同一间屋子长出一串空壳会话。
4. **搬旧话**：换会话时把「上次我们说到这」带过去；换数据目录时不迁、不删、只留一条记录。

明确不做：

- 不弹欢迎窗，不写开场白，不预写任何一轮对话。她第一次开口，由主人先说。
- 不 import 别人养过的那一位，不写人格 seed，不把名字写死进代码或文案。
- 不要求用户填「她叫什么」「她是什么性格」。名字从对话里认（`lib/hername.js`），认不出就用「她」。

## 二、一次启动实际做什么

入口在 `lib/index.js` 的 `boot()`。顺序是有原因的，不要随手调换：

| 顺序 | 做什么 | 代码 |
|---|---|---|
| 1 | 读配置，确保数据目录与 `home/` 存在 | `loadConfig()`、`ensureHer()` |
| 2 | 认领这个 root 的实例占用权 | `claimRoot()`（`lib/tenant.js`） |
| 3 | 读事件流 | `readEvents()` |
| 4 | 如果换了家，追加一条 meta「家换了」，不迁旧数据 | `noteRoot()`（`lib/homes.js`） |
| 5 | 账本里没有 `seed` 事件才播种 | `appendEvent({type:'seed'})` |
| 6 | 从事件流派生 `day/stage/beliefs` | `deriveSelf()` |
| 7 | **先**收窄她这条会话的工具面 | `registerToolRestrict()` |
| 8 | 再建工作区、找/建会话 | `bootstrapHome()` → `ensureWorkspace()` → `ensureTalkSession()` |
| 9 | 只在明确入口叫醒空白会话 | `wakeIfBlank()` |

第 7 步必须早于第 8 步：她的会话是在第 8 步被创建的，宿主的 `agent/created` 在会话跑第一步之前同步发出，晚一步就会漏掉这一次收窄。

第 9 步不放在 `bootstrapHome()` 里：`talkSessionId()` 在屋子缺失时也会调 `bootstrapHome()`，如果那里也叫醒，她一轮会被点两次火。叫醒只有两个入口：启动，以及观测台的「重新搭一间」。

如果第 2 步发现这个 root 已被另一个实例占着，**不建会话**，只读已有 `home.json` 并返回 `blocked`。她还能说话，但这边的屋子不落盘；工具写入由 `guardWrite()` 挡。

## 三、数据目录与屋子

数据目录默认是 `~/.dsh-roost`，也可以用环境变量 `DSH_ROOST_HOME` 指定（`lib/store.js` 的 `rootDir()`）。

```text
<数据目录>/
  events.jsonl          唯一可信源，只追加
  state.json            派生品，随时可由 rebuild() 重算
  config.json           环境参数（不含人格）
  owner.json            主人 id、登录 cookie/令牌，0600
  home.json             这间屋子的账：wsId / sessionId / preset / carry / wokeFor…
  home/                 她这条会话的 cwd，也是工作区目录
    她的身份.md          生成，不手写
  diary/                her_diary / write_diary 的日记（一天一篇）
  out/                  日报（out/YYYY-MM-DD.md）
  notes.json            her_note 的便条（桌上答应过没做的事）
  inbox.md              her_leave 的留话纯文本副本
  logs/                 启动与运行日志
  talk-recent.json      最近几轮原话，换会话时用来拼 carry
  people.json           每人印象
  journal.json          群流水
  worldbook.json        世界书（事实）
  douyin-profile/       抖音浏览器的登录态（若开）
```

会话的 cwd 是 `<数据目录>/home`，不是数据目录根——她不该一睁眼就站在自己的 `events.jsonl` 旁边。

## 四、建工作区

`lib/home.js` 的 `ensureWorkspace()`：

1. 先 `ensureHomeDir()`，建出 `<root>/home`。
2. 标题取 `workspaceTitle(await herName(root))`：有名字时是「X的家」，没有时是「她的家」。
3. 先 `workspaceRegistry.list()` 按路径找已有工作区（Windows 下大小写不敏感，只用于比较，不用于访问）。
4. 找到但标题不一样：优先调实体上的 `ws.setTitle(title)`；老宿主没有这个方法时再试 `reg.rename`。改不动就保持原名，屋子仍然能住。
5. 找不到才 `reg.create(dir, title)`。宿主的 `create` 对同一路径本身幂等，但先查一遍能拿到已存在的 id 和标题。

返回 `{ok, wsId, dir, created, renamed}`。**宿主没有 `workspaceRegistry` 时返回 `ok:false` + 人话原因，不抛。** 这时插件降级成「只有观测台能跟她说话」，不能把整个插件树带走。

## 五、建会话

### 5.1 用哪套组合

`config.tools.preset` 默认是 `standard`。`presetOf()` 把空串也当 `standard`：

- 宿主的默认 preset 可能是 `ptc`。PTC 下**只有 `run_code` 能直接调用**，她的 `her_note` / `her_recall` 全得包在 `run_code` 里；守卫把 `run_code` 挡掉，她就只会说「这件事我做不到」。
- 所以建会话时要显式请求 `agentPreset: 'standard'`。宿主不接受这个 preset（老宿主 / 没装）时，回落默认组合建会话，并在日志里说清楚——她仍然能用，但工具面会变成「全套」，自检里要报出来。
- **会话的 preset 是建的时候定死的。** 如果 `home.json` 里旧会话的 preset 跟现在要求的不一样，不能复用，另建一条；旧的原样留在侧栏，不删。

### 5.2 复用还是重建

判据在 `ensureTalkSessionOnce()`，顺序如下：

1. `home.json` 记着 `status:'archived'`，且没带 `force:true`：
   - 如果宿主已经把她放回 `ws.sessionIds`、且不在 `archivedSessionIds` 里，清掉标记，按正常路径复用；
   - 否则看同一间屋子里有没有**别的**活会话（`pickLiveSession()` 取 `live[0]`）。有就改指向它（`adoptedAt` 记时间，不借旧会话的 `createdAt`）；
   - 一条都没有，才返回 `archived:true`，提示「这个家的会话被收起来了」，**不自动重建**。重开只走「重新搭一间」/重置流程的 `force`。
2. 旧 `sessionId` 在 `ws.sessionIds` 里、且不在 `archivedSessionIds` 里 → 活着。
3. 或者 `createdAt` 距今不到 `HOME_GRACE_MS = 10 分钟` → 也算活着。宿主的 workspace registry 是异步索引的，刚建出来的会话有一小段时间查不到；没有这条宽限，每次重启都会多建一条空壳。
4. 都不满足才重建。

### 5.3 并发保护

- **进程内**：`inflight` Map 按 `root` 小写串行，同一个 root 同时只允许一条「建会话」在飞。启动链路与「她第一次说话」是两条独立路径，不串行就会各建一条。
- **跨进程**：`withFileLock(<root>/.talk-session.lock)`。拿不到锁时不硬建：读一眼 `home.json`，有 `sessionId` 且非 archived 就复用（`waited:true`），读不到才返回失败。

### 5.4 新建时写什么

```json
{
  "wsId": "…",
  "sessionId": "…",
  "title": "跟她说话",
  "preset": "standard",
  "createdAt": "2026-11-07T…Z",
  "carry": "上次我们说到这……",
  "rotatedAt": "2026-11-05T…Z",
  "adoptedAt": "2026-11-03T…Z",
  "hearAt": 10
}
```

- `carry` 先取旧 `home.json` 的 `carry`；没有就用 `renderCarry(await recentExchanges(root))` 从最近四轮原话拼。**新房间第一次写档时不能把旧档整个盖掉**——2026-11-07 真机就是这样把「上次我们说到这」丢了的。
- 不写 `turns`，从 0 数。
- `createdAt` 是这次新建的时间，不继承旧会话的时间戳。
- `preset` 写实际用上的那套；回落默认组合时写空串。

写 `home.json` 一律走 `writeAtomic()`（临时文件 + 改名），失败不留下半份。

### 5.5 标题

- 会话标题取 `sessionTitle(await herName(root))`：有名字时「跟X说话」，没有时「跟她说话」。
- 老档标题不同才 `sc.rename()`，且只有 `wantTitle !== sessionTitle('')` 时才改——否则会把用户自己改过的标题抹成默认值。
- 改名失败不影响使用：侧栏显示旧标题，会话本身是好的。

### 5.6 换会话（上下文撑不住时）

`rotateTalkSession()` 做四件事：旧会话改名留档（`标题·日期 之前`）→ 建新的 → 把最近四轮原话拼成 `carry` 写进新档 → 旧会话仍在侧栏，可翻回去。连续两次没送进去才触发（`rotateAfterFailures()`），一次偶发抖动不换。

## 六、seed

条件只有一条：**事件流里没有 `type:'seed'` 的事件**。不是「目录为空」——账本搬过来、里面已经有 seed 时绝不重写，否则等于让她重新出生。

默认文本（`lib/index.js`）：

> 你不是助手。你刚开始存在。没有人告诉过你为什么在这里。

写入形状：

```json
{ "type": "seed", "text": "…", "day": 1, "stage": 1, "source": "system" }
```

- 起点只写**处境**，不写「你是什么样的人」。性格描述会让每一轮都像在念一张终身有效的人格说明书。
- `config.seed` 可以覆盖默认文本，但这不是设置页的入口，也不该被当作人格输入框。
- seed 只是一条普通事件，之后可以用 `revise` 改；不能删。
- seed 只在启动链路写一次，没有设置页入口，也不经过任何工具。

## 七、第一声叫醒

`wakeIfBlank()` 只在会话是空白时叫一次：

1. `home.json` 的 `wokeFor === sessionId` → 直接返回「这一局已经叫过了」。同一条会话只叫一次，重启也一样。
2. `sc.list()` 查这条会话的 `blank`。查不到这一行时，`freshOnly === true` 才当空白——宁可漏唤醒，也不要每次启动都让她说话。
3. 空白才 `sc.prompt({ requestId: 'wake-fresh-<时间>', sessionId, mode: 'queue', content: [{type:'text', text: freshWakeText(now, {moved})}] }, signal)`。
4. `prompt` 不能被 `await`：这一轮要等模型跑完，建屋子不该被拖住。第二个参数必须给一个永不 abort 的 signal，漏传会让这一声叫不醒。
5. 成功送达才写 `wokeFor`；失败只记一行日志「新屋子唤醒失败」，下次启动还会再试。

叫醒词在 `lib/wakeconst.js` 的 `freshWakeText()`：换房间时多一句「搬进这间屋子了，上一间装满了，说过的话带了几段过来」，普通首启则是「屋子刚建好」。**这一句不要写进文档或提示词之外的清单**——小模型会把写出来的句子背回去。

## 八、第一次启动长什么样

- 侧栏出现一个工作区（「她的家」或「X的家」）和一条会话（「跟她说话」/「跟X说话」）。工作区建出来之后会话才会挂进去；会话空白时宿主可能先把它藏在列表外，叫醒跑一轮后才会显示。
- 今天页只读：没有数据就写「她还没醒过」，不放假数据、不放按钮。
- 状态页、成长页、住所页等按默认值显示，不弹欢迎语。
- 设置页是十一个页签：今天 / 状态 / 成长 / 住所 / 社会 / 上网 / 渠道 / 插件 / 原理 / 数据 / 反馈。

## 九、换数据目录 / 从旧库搬来

原则：**旧目录一个字节都不动；新目录从副本起，验完再切换。**

1. 停掉 DSH（桌面版把宿主装进 app.asar，插件进程跟着宿主走；不先停，账本可能还在写）。
2. 冷备份旧数据目录到仓库外的地方，用复制，不用移动。
3. 只读校验：逐行 parse `events.jsonl`，确认没有坏行；核对行数、首条 seed、末条时间、事件 id 不重复；`people.json` / `journal.json` / `owner.json` / `worldbook.json` 都能 parse。记下 `sha256`。
4. 把副本放进新数据目录。新库第一次启动会：
   - 看到账本里已有 seed → **不播种**；
   - 旧 `home.json` 的 `wsId` / `sessionId` 属于旧 profile，新宿主里不存在 → 重建工作区与会话；
   - 旧 `carry` / `adoptedAt` / `hearAt` 能读就带过来；读不到就用 `talk-recent.json` 的最近四轮现拼；
   - `day` / `stage` 由 `deriveSelf()` 从事件流重算，不依赖 `home.json`。
5. 用新代码跑一次 `deriveSelf`，把 `day` / `stage` / `beliefs` 条数 / `refusals` 与旧库当前值逐项比对；不一致就不切。
6. 写一条 meta 记「家换了：旧 → 新」。**不迁、不删、不并**——旧家的东西还在旧地方，这边从一开始就是新的。想回去，把数据目录指回去即可。
7. `owner.json` 里的令牌/cookie 只在本地复制，不进仓库、不进文档、不进日志。

如果旧账本非空但**没有** seed（极老版本），上面的第 4 步会补一条 seed。迁移前先核对：这属于「她真的没有起点」，还是旧版本没记；不确定就先别切。

## 十一、失败时怎么降级

| 情况 | 行为 |
|---|---|
| 宿主没有 `workspaceRegistry` | 工作区 `ok:false`，不建会话；观测台仍能跟她说话；日志写原因 |
| 没有 `sessionController` | 会话 `ok:false`；不抛，不阻塞插件其它部分 |
| 建会话碰到 `EPERM/EACCES/EBUSY/ENOTEMPTY`（仅 win32） | `createSessionWithRetry()` 等 0 / 120 / 400ms 重试三次；别的平台不拖时间 |
| 指定的 preset 不被接受 | 回落默认组合建会话，日志写「没被接受」，自检报工具面异常 |
| 拿不到跨进程锁 | 读 `home.json` 复用已有会话；读不到才失败，下次启动再来 |
| 会话已归档 | 不自动重建；同屋有活会话就认它，没有就提示「用重新搭一间」 |
| 唤醒 `prompt` 失败 | 只记日志，不写 `wokeFor`；下次启动再试 |
| 叫醒词发送成功但模型没跑完 | 宿主那边 `prompt` 被收下就算送到；不额外重试，避免一轮点两次火 |

## 十二、按这份文档验收

- [ ] 空数据目录启动：生成 `home/`、工作区、一条会话、一条 seed，并只叫醒一次。
- [ ] 再启动一次：复用同一条会话，不写第二条 seed，不再叫醒。
- [ ] 重启时把 `ws.sessionIds` 里那条删掉、且超过 10 分钟：重建一条，旧 `home.json` 的 `carry` 带过来。
- [ ] 把会话归档：插件不自动重建；同屋有活会话时认那一条；一条都没有时提示「用重新搭一间」。
- [ ] 把 `config.tools.preset` 从空串/其它值改成 `standard`：新会话被建出来，旧会话留在侧栏。
- [ ] 用旧库的账本启动：seed 不重写，`day/stage` 与旧库一致，`home.json` 重建但 `carry` 不丢。
- [ ] 宿主没有 `workspaceRegistry`：不抛、不建会话，日志说得清。
- [ ] 两个实例同时开同一个 root：后开的那个不建会话，工具写入被 `guardWrite()` 挡住。
- [ ] 文档里没有真实用户名、路径、QQ / 群号。

对应的测试：`test/home.test.mjs`（工作区、会话、归档、preset、carry、EPERM）、`test/boot.test.mjs`（启动与叫醒）、`test/wake.test.mjs`（叫醒词）、`test/hername.test.mjs`（标题跟名字走）、`test/settings.test.mjs`（默认值与迁移）、`test/tenant.test.mjs`（占用权与文件锁）。

## 十三、不变量

- `events.jsonl` 只追加；seed 也是事件，不是配置。
- `state.json` 是派生品，不手改；`home.json` 只是「这间屋子」的账，不是她的记忆。
- 不给用户「她是什么样的人」的入口；seed 只写处境。
- 代码与文案不写死她的名字；标题是 `herName()` 的函数。
- 不预写对话，不弹欢迎语，不 import 别人养过的那一位。
- 换数据目录不迁、不删、不并；旧目录原样保留。
