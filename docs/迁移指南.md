# 迁移指南：把「他说过的话」搬进来

2026-11-10 起，`tools/import.mjs` 支持把别的项目里的旧对话导入，只写成 `heard`。这是 `AGENTS.md` §2 的**唯一窄例外**，条件写在那里，这里只讲怎么用。

## 能带什么，不能带什么

| 带得走 | 带不走 |
| --- | --- |
| 那个人说过的话（`user/message`、SillyTavern 的 `is_user`） | 她在那边说过的话（换了人设提示词生成的，搬进来等于把人设效果一起搬） |
| 原话的时间顺序（压成导入前的一天内） | 人设卡、`core.md`、`topics/*.md`、记忆结论、好感度数字 |
| 来源与条数的留痕（`import-mark:`） | 原来的阶段、称呼、认识天数 |

一句话：**你能带走的是你们之间发生过的事，带不走同一个人。** 名字和住处进来之后重新起。

## 用法

```bash
# 先干跑，看会读到什么、丢掉什么（不写盘）
node tools/import.mjs --from "C:\Users\by_ch\.dsh\sessions\D--fish" --limit 200

# 确认没问题再写
node tools/import.mjs --from "C:\Users\by_ch\.dsh\sessions\D--fish" --limit 200 --write
```

参数：

- `--from <文件或目录>`：目录会递归找 `.zstd`（DSH 会话）、`.jsonl`（SillyTavern 导出）、`.txt`（纯文本，一行一句）。
- `--limit N`：最多导入 N 句。
- `--write`：真的写事件；不加就是干跑。
- `--root DIR`：数据目录，默认 `~/.dsh-perch`。

## 它会做什么

1. 解 DSH 的 `session.v4.jsonl.zstd`（多帧 zstd，逐帧解），只取 `user/message`；SillyTavern 只取 `is_user: true` 的 `mes`。
2. 过一遍 `guard.stripScaffold` 去掉脚手架；空句、超过 2000 字的句子丢掉；与账上已有 `heard` 重复的（按 sha1）丢掉。
3. 写一条 `meta import-mark:<来源>:<条数>`，再把每句写成 `heard`（`source: system`、`channel: dsh`、`visibility: private`、`origin: owner`）。
4. 时间等比例压到「导入前 8 小时」这一带，顺序不变；阶段与「认识多久」从今天重新算。
5. 下一次叫醒时，`lib/scheduler.js` 会用一句话说明来历（「从别处搬来的旧对话，不是在这里发生的」），只说一次，写 `import-told:<markId>`。

## 别做的事

- **别导她的回复**。工具根本不读那一侧，改了也别。
- **干跑时看样例**。DSH 的工作区里混着「他给别的 AI 下的指令」（「你是做只读调研的……」），那些是他对工具说的话，不是对她说的话。工具会滤掉运行时上下文和系统提醒，但分不出这一类——`--limit` 先小，样例看对了再放大。
- **别导别人的私聊**。DSH 工作区里如果有别人的会话，先自己筛掉；导进来就是「她听过」，账本里洗不掉。
- **别一次导几万句**。前 200 句是经历，后 2 万句是把她的判断泡在旧水里；建议先 `--limit 200` 试，觉得有用再补。
- **别指望它保住原来的关系**。阶段从第 1 天重新走，她对你的称呼也会重新长。

## 回滚

导入是追加式的，删不掉单条；不想要了只有两条路：

- 导入前先 `cp ~/.dsh-perch/events.jsonl ~/.dsh-perch/events.jsonl.bak`；
- 或者接受它——旧话已经在账上，用 `her_recall` 能翻到，但不进活跃召回的部分由 `foldOlderBeliefs` 自然折叠。
