# 迁移指南：把「对方说过的话」搬进来

这份指南写给「在别的项目里养过一位，现在想搬到这里」的人。能搬的只有**对方说过的话**，不是那位本身；这是 `AGENTS.md` §2 的唯一窄例外，条件以那里为准。

## 一、能搬什么，不能搬什么

| 能搬 | 不能搬 |
| --- | --- |
| 对方说过的话（DSH 的 `user/message`、SillyTavern 的 `is_user: true`、纯文本里的句子） | 那位在旧项目里说过的话（换了人设提示词生成的，搬进来等于把人设效果一起搬） |
| 原话的先后顺序（时间会压缩，见第四节） | 人设卡、`core.md`、`topics/*.md`、记忆库、好感度/亲密度数字 |
| 一条来源与条数的留痕（`import-mark:`） | 原来的阶段、称呼、认识天数、关系结论 |

落地时只写一种事件：`heard`（`source: system`、`channel: dsh`、`visibility: private`、`origin: owner`）。她不把旧话当成自己说过的话，也不会因此跳过四个阶段。

## 二、怎么交

先建一个来源目录：

```
D:\fish\_import\<来源名>\
```

把文件放进去，按来源选一种：

- **SillyTavern**：`chats\*.jsonl`。工具只读 `is_user: true` 的那一侧，`mes` 就是原话。
- **DSH**：`%USERPROFILE%\.dsh\sessions\<工作区编码>\<会话id>\session.v4.jsonl.zstd`。可以只给一个会话文件，也可以给整个工作区目录；工具会递归找 `.zstd`，逐帧解压，只取 `user/message`。
- **纯文本**：`.txt`，一行一句。写成 `名字：内容` 时，名字是 `她/你/ai/assistant/bot` 的行会被跳过；其余名字只取冒号后的内容。

同目录再放一份 `说明.md`，四栏，给人看，也方便以后追溯：

```markdown
| 来源 | 时间范围 | 条数 | 隐私 |
| --- | --- | --- | --- |
| SillyTavern / <项目名> | 2025-03-01 ~ 2025-08-12 | 1234 句（对方说的） | 只有我们俩，没有别人的私聊 |
```

> `说明.md` 不会被工具读取；工具真正用来留痕的是 `--from` 指向的**目录名**。

## 三、怎么跑

### A. 文件在你这边（默认）

在仓库根目录：

```bash
# 先干跑：不写盘，只出报告
node tools/import.mjs --from "D:\fish\_import\<来源名>" --limit 200

# 看报告里的「读到 / 可用 / 丢弃 / 样例 / 原始时间」都对，再写
node tools/import.mjs --from "D:\fish\_import\<来源名>" --limit 200 --write
```

干跑报告会写：

- 文件数、读到多少句对方的话、可用多少句；
- 丢弃原因（运行时上下文、空句、超过 2000 字、重复）；
- 最多 5 条样例；
- 原始时间范围，以及「已压成导入前的一天内」；
- 加 `--write` 后的写入条数与 `import-mark` 事件 id。

`--limit 200` 是建议值：先小批量看样例对不对，再放大。不要一上来导几万句。

### B. 对方自己跑，把账本发回来

对方 `git clone https://github.com/bychance6600/dsh-perch`（零依赖，不用 `npm install`），在仓库根目录跑：

```bash
# 干跑，写到临时目录，不碰对方自己的 ~/.dsh-perch
node tools/import.mjs --from "<对方的会话目录>" --root "D:\temp\perch-import" --limit 200

# 确认后写入临时目录
node tools/import.mjs --from "<对方的会话目录>" --root "D:\temp\perch-import" --limit 200 --write
```

把 `D:\temp\perch-import\events.jsonl` 发回来。你这边只接两类事件：

```bash
# 先干跑，看会接多少条
node tools/import.mjs --merge "D:\fish\_import\<来源名>\events.jsonl"

# 确认后合并进 ~/.dsh-perch
node tools/import.mjs --merge "D:\fish\_import\<来源名>\events.jsonl" --write
```

`--merge` 只接 `heard` 与 `import-mark`，别的类型（包括那位在旧项目里说过的话）一律不接；与本机账上重复的 `heard` 按原话的 sha1 跳过。时间沿用对方那份，不再重新压缩。

### 参数（以 `tools/import.mjs` 为准）

| 参数 | 作用 |
| --- | --- |
| `--from <文件或目录>` | 导入来源；目录会递归找 `.zstd` / `.jsonl` / `.txt` |
| `--merge <events.jsonl>` | 只合并对面导出的 `heard` 与 `import-mark` |
| `--write` | 真的写盘；不加就是干跑 |
| `--root <目录>` | 数据目录，默认 `~/.dsh-perch`；对面跑时用来写临时目录 |
| `--limit N` | 最多导入 N 句 |
| `--json` | 报告以 JSON 输出 |
| `--help` | 用法 |

没有 `--source` 参数；来源名来自 `--from` 的目录名。

## 四、边界

- **时间会压缩**：原话时间等比例放进「导入前 8 小时到 2 小时」这 6 小时窗口，顺序不变。阶段、认识天数、称呼都从今天重新算。
- **留一条 mark**：每次真正写入前写 `meta import-mark:<目录名>:<条数>`。条数是这一批**可用**的句数（正常情况下等于写入数），不是读到的总数。全部重复时不会写新的 mark。
- **第一次叫醒会说明来历**：下一次叫醒时，`lib/scheduler.js` 会说一句「你账上有一批从别处搬来的旧对话，共 N 句，都是对方说过的话，不是在这里发生的。你知道那些话，但没有自己当时怎么答的记忆——这一世从今天起。」然后写 `import-told:<markId>`，同一批只说一次。
- **重复导入不会写第二遍**：同一句话按 sha1 去重，已经在本机 `heard` 里的不会再写。注意 `--merge` 会把发回来文件里的 `import-mark` 也照写；同一份导出只合并一次，别反复合并。
- **改名字不能在导入文件里改**：没有名字字段。搬完以后在会话里新说一句，比如「以后你就叫 <名字>」，由 `lib/hername.js` 从事件流里认；写进 `说明.md` 或旧对话里都不算。
- **只搬对方的话**：她/那位在旧项目里的回复一条都不读。人设卡、记忆库、好感度也不读——这些不是「你们之间发生过的事」。

## 五、回滚

导入是追加写，最稳的回滚是**导入前备份**：

```bash
cp ~/.dsh-perch/events.jsonl ~/.dsh-perch/events.jsonl.bak
```

只想撤这一批、不丢后面的事件，先停 DSH（别让叫醒或会话继续写），再按文件位置删：

1. 备份当前 `events.jsonl`。
2. 找到 `"text":"import-mark:<目录名>:<N>"` 那一行。
3. 这一行后面紧跟的 `N` 条 `"type":"heard"` 就是这一批；删掉这 N 条，再删 mark 本身。
4. 如果已经叫醒过，再删对应的 `"text":"import-told:<markId>"`，免得下一次叫醒对不上。

**不要按时间戳筛。** 这批 `heard` 用的是压缩后的旧时间，落在导入前 2–8 小时，时间上比 `import-mark` 更早；按「mark 之后的时间」删会一条也删不到。它们在文件里是紧跟在 mark 后面的连续块。

如果备份就是导入前的状态，直接恢复备份更省事；代价是导入之后新长出来的事件也会一起回退。

## 六、常见问题

- **报告里「读到」和「可用」对不上**：正常。运行时上下文、系统提醒、空句、超过 2000 字、和账上重复的都会被丢掉；看「丢弃」那一行。
- **DSH 的 `.zstd` 解不开**：工具按多帧 zstd 逐帧解，坏帧跳过。仍然读不到时，把那个会话目录整体给 `--from`，别只给一个截断的文件。
- **SillyTavern 的 `.json` 不认**：只认 `.jsonl`。先导出成 jsonl。
- **纯文本里两个人都说话了**：工具分不出谁是谁；写成 `名字：内容`，并确保对方的名字不是 `她/你/ai/assistant/bot`。分不清就先手工拆成两边，只留对方那份。
- **导入后她没立刻提这件事**：说明还没叫醒。下一次叫醒才会说，且只说一次。
- **能不能把她的回复也搬来**：不能。这不是参数问题，是 `AGENTS.md` §2 的硬条件；改了工具也不该这么做。
- **隐私**：只导你获得许可的对话；别人的私聊、群聊里第三人的话不要混进来。导进来就是「她听过」，账本按设计只追加。
