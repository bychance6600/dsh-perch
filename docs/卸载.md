# 卸载

> 卸载是四件事，不是一件：**插件、数据、桥、身体**。前两件必须处理，后两件看你怎么装的。
> 无论卸到哪一步，**先备份账本**——它是她唯一不能从别处恢复的东西。

---

## 0. 先备份（这一步别省）

她的全部经历只在本地一个文件里：

- **账本**：`~/.dsh-perch/events.jsonl`（Windows：`C:\Users\<你>\.dsh-perch\events.jsonl`）——只追加，删了没有云端可恢复，也没有「账号」能重登。
- 身份、日记、便条、世界书、配置也在这个目录里；大多能重建，但重装后想原样回来，靠的是备份。

两种备份方式，选一种：

1. **整目录拷走**（最稳）：把 `~/.dsh-perch` 整个复制到别处，改名成 `dsh-perch-backup-20261127` 之类。
2. **设置 → 数据 → 备份**：得到一个 `.json`（含账本与派生文件；不打包日志和旧备份）。

只要备份过，后面删错还能捞回来。**先备份，再动手。**

---

## 1. 卸插件

插件装在 DSH 的某个 profile 里，不在 `~/.dsh-perch`。默认 profile 是 `desktop`：

- Windows：`C:\Users\<你>\.dsh\profiles\desktop\`
- macOS / Linux：`~/.dsh/profiles/desktop/`

先看 `package.json`：`dsh-perch` 在 `dependencies` 里，也在 `dsh.profile.bundles` 数组里。**两处都要去掉**。

### 装法一：pnpm / npm 装的（含用 install.ps1 装的）

`install.ps1` 只是替你做「`pnpm add` + 写 bundles」，它没有卸载功能，反向做同样两步：

```bash
cd ~/.dsh/profiles/desktop      # Windows: cd C:\Users\<你>\.dsh\profiles\desktop
pnpm remove dsh-perch           # 用 npm 装的换成 npm uninstall dsh-perch
```

然后手动编辑这个目录下的 `package.json`，从 `dsh.profile.bundles` 里删掉 `"dsh-perch"` 这一项。

### 装法二：link 本机源码

`pnpm remove dsh-perch` 只会断开链接，**不会删你的源码目录**（`D:\path\to\dsh-perch` 还在）。同样别忘删 `dsh.profile.bundles` 里的那一项；源码目录要不要删，你自己定。

### 卸完

1. **重启 DSH**——运行中的插件包不会热卸载。
2. 打开设置，「她」那一页应该消失。
3. 日志里不再出现 `dsh-perch` 开头的版本行（`~/.dsh-perch/logs/dsh-perch.log` 还在，只是不再写入）。

> 只想「暂时不用」：不删插件，直接停掉它就行（设置里关掉渠道与唤睡）。数据目录一点不动。

## 2. 数据目录

默认 `~/.dsh-perch`（Windows：`C:\Users\<你>\.dsh-perch`）。里面的东西：

```
events.jsonl          账本，唯一可信源，只追加     ← 不可再生
state.json            派生品，可从账本重算
config.json           环境参数（不含人格）
owner.json            主人 id、渠道身份 id、登录 cookie（0600）
home.json / home/     这间屋子、她的工作区
diary/ out/           日记、日报
notes.json inbox.md   便条、留话
people.json journal.json  印象、群流水
worldbook.json        世界书（事实）
media/                她看过的图、收发的附件
douyin-profile/       抖音登录态（开过才有）
logs/ cache/          日志、体检缓存（可删）
```

**删之前**：至少确认 `events.jsonl` 已备份。想留个后悔的机会，就改名封存而不是直接删：

```bash
# macOS / Linux
mv ~/.dsh-perch ~/.dsh-perch-old-20261127

# Windows PowerShell
Rename-Item "$env:USERPROFILE\.dsh-perch" ".dsh-perch-old-20261127"
```

确认不要了再删：

```bash
rm -rf ~/.dsh-perch
# Windows PowerShell
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh-perch"
```

> `owner.json` 里有渠道登录态，删前别把这个文件随手发给别人。
> 设置 → 数据 → 从头开始，也是把整个目录改名封存，不是原地抹掉；那条路不算卸载。

## 3. 桥（NapCat / SnowLuma）

桥是**独立进程**：负责 QQ 登录，插件只是连它的客户端。卸插件不会停桥，桥也不会碰 `~/.dsh-perch`。

- **本机直接跑**：从托盘退出，或任务管理器里结束 `NapCat.exe` / `SnowLuma.exe` 一类进程。
- **Docker 跑的**：
  ```bash
  docker ps                     # 看名字，例如 napcat
  docker stop napcat
  docker rm napcat              # 容器删了；挂载目录里的登录态还在
  docker rmi <镜像名>            # 可选：镜像也删
  ```
- 登录态在桥自己的挂载目录里（例如 `C:\Users\<你>\fish\napcat`），不在 `~/.dsh-perch`；要连登录态一起清，删那个目录。
- 桥停了，她只是不再在 QQ 里说话；DSH 会话那一边不受影响。

---

## 4. 身体（桌宠）

桌宠（透明置顶小窗）是**另一个独立项目**，不是这个插件的一部分，装法与卸载都跟它自己的说明走（Electron 应用：控制面板卸载，或删它的安装目录）。

不装身体不影响插件；卸掉身体也不影响她的账本。

---

## 5. 重装与恢复

1. 按 [README](../README.md) 的装法把插件装回去，重启 DSH。
2. 数据：把备份的 `~/.dsh-perch` 放回默认位置；或者用设置 → 数据 → 恢复，选之前那份 `.json`。
3. 打开设置 → 她：能看到「今天」「状态」页，日志第一行有版本号，就说明接上了。
4. 换机器同理：整目录带走，按安装步骤重装插件即可；工作区 ID 会变，但账本与身份跟着走。

> 版本跨得远时，先在**旧版本**上备份，再升级；恢复后如果页面提示迁移，照提示做。
