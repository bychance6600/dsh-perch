# 子包讨论稿：只读看项目 / 代码

状态：讨论稿（2026-11-07），未实现。这份文档只把问题、边界和可选方案摆出来，供另开一个会话商量；不先写代码，也不先定包名。

一句话：这不是给她加人格，也不是开放通用文件权限；是一个可选的、只读的、按根目录授权的「看项目」工具。

---

## 一、为什么现在提

她最近想看一个放在本机的项目（dsh-pet 这类），但当前没有一个合适的口子：

- web_fetch 只能读公开 URL。GitHub 上的公开仓库可以读，本机目录、私有仓库、没联网时的源码读不到。
- 通用文件工具 read / glob / grep / bash 不能放进 config.tools.allow。它们不是按目录授权的：一放行，她就能读到 ~/.dsh-perch/home/她的身份.md、config.json、state.json、douyin-profile 这些地方，直接撞上「不能读自己的数值与设定」；bash 还能写，撞上「不能改自己」。
- 直接给她一个通用 read 也不是办法：今天想读项目，明天就能读整个家目录。权限口子一旦开成「任意路径」，后面很难收。

所以需要的是一个窄口：只读、只能看主人明确授权的那几个根目录、不能写、不能执行、不能自己加目录。做成可选子包，不装就没有这个能力。

---

## 二、目标与非目标

### 目标

1. 在主人配置的根目录内，列出目录、读文本文件。
2. 返回相对路径和行号，方便她引用「哪个文件的哪一行」。
3. 只读。任何写、删、改名、执行、安装依赖都不在能力范围内。
4. 默认关闭；没配置根目录时，她读不到任何东西。
5. 不装子包时，主包照常启动，她的 12 个工具不受影响。

### 非目标

- 不做通用文件管理器，不做 read / glob / grep / bash 的替代品。
- 不做代码执行、跑测试、装依赖、启动项目。
- 不做语义索引、向量检索、AST 调用图、自动把整个仓库塞进提示词。
- 不读 ~/.dsh-perch、~/.dsh、身份文档、配置、状态、登录态。
- 不替代 web_fetch。公开网页和 GitHub 文件仍走 web_fetch；这个子包只读本机授权目录。
- 不是渠道。它不接消息、不回复、不建 channels.* 配置；它是一个工具。

---

## 三、三种做法，建议只做第一种

### 方案 A：只读文件浏览器（推荐 v1）

能力只有两个：

- tree：列一层或两层目录，返回相对路径、类型、大小。
- read：读一个文本文件，支持起始行和行数。

优点：攻击面最小，实现最短，测试最好写。看一个项目的源码，绝大多数时候「列目录 + 读文件」就够了。

### 方案 B：A + 关键词搜索（建议 v2）

加一个 search：在授权根内按字面量搜关键词，返回命中的文件、行号、该行文本。

看代码确实需要搜索，但搜索会带来遍历整个仓库的成本和更多边界（忽略目录、二进制、超大文件、命中上限）。第一版先不做，等 A 在真机上用顺了再加。

如果做，限制死：

- 只搜文本文件；
- 只做字面量 indexOf，不接受用户正则（避免 ReDoS 和复杂语义）；
- 最多 50 条命中、20 个文件、总输出 32KB；
- 跳过 .git、node_modules、dist、build、coverage 等默认忽略目录；
- 超过 2 秒或 5000 个文件就停，返回「只搜了一部分」。

### 方案 C：代码理解（不做）

AST、符号表、调用图、依赖图。听起来很强，实际上会把一个权限问题变成一个大工程，而且她真正需要的是「能自己读」，不是「别人替她总结」。不做。

这些都可以商量，下面只是建议。

| 项 | 建议 | 理由 |

- dependencies / peerDependencies / devDependencies: 全部 {}（零依赖铁律）

## 五、接口草案

### 工具调用

    {
      "what": "tree",
      "root": "dsh-pet",
      "path": "",
      "depth": 2
    }

    {
      "what": "read",
      "root": "dsh-pet",
      "path": "src/index.ts",
      "from": 1,
      "lines": 200
    }

    {
      "what": "search",
      "root": "dsh-pet",
      "query": "createPlugin",
      "limit": 20
    }

参数含义：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| what | tree / read / search | 动作；v1 只有前两个 |
| root | string，可选 | 配置里的根别名；只有一个根时可省略 |
| path | string，可选 | 相对根的路径；空 = 根本身 |
| from | number，可选 | 起始行，1 起；默认 1 |
| lines | number，可选 | 最多读多少行；默认 200，上限 400 |
| depth | number，可选 | tree 的深度；默认 1，上限 2 |
| query | string，可选 | search 的字面量关键词 |
| limit | number，可选 | search 最多几条命中；默认 20，上限 50 |

### 返回

成功：

    {
      "ok": true,
      "what": "read",
      "root": "dsh-pet",
      "path": "src/index.ts",
      "from": 1,
      "to": 120,
      "totalLines": 340,
      "truncated": true,
      "text": "1 | import ...\n2 | ..."
    }

失败：

    {
      "ok": false,
      "why": "这个路径不在我能看的范围里。",
      "code": "outside-root"
    }

约定：

- 返回里不出现绝对路径，只出现根别名和相对路径。
- 错误信息不泄露家目录、根的真实路径、文件是否存在之外的任何东西。
- 读文件时行号写进文本，格式统一为「行号 | 内容」；这样她引用时不用自己数。
- truncated 明确告诉她「后面还有，没读完」，不要假装读完。
- 二进制、超大文件、敏感文件名直接拒绝，并给出人能看懂的原因。

## 六、安全边界（最重要的一节）

### 1. 根目录由主人配置，默认空

配置里只存主人明确填的根。默认：

    {
      "peek": {
        "enabled": false,
        "roots": [],
        "maxFileBytes": 262144,
        "maxLines": 400,
        "search": false
      }
    }

- enabled:false 或 roots:[] 时，工具不读任何文件。
- 每个根有 name（别名）和 path（绝对路径）。别名只允许字母、数字、下划线、短横线，长度不超过 32。
- 根必须存在、必须是目录、必须能 realpath。配置保存时做一次规范化；每次调用再解析一次，防止中途被换成链接。

### 2. 路径必须落在根内

每次请求按下面顺序校验：

1. 拒绝空字节、NUL、URL 编码后的 %00（不做 URL 解码，直接拒绝可疑字符）。
2. 拒绝绝对路径、盘符路径（C: 开头）、UNC（两个反斜杠开头）、以及 \\?\ 和 \\.\ 设备路径。
3. 把 path 按当前平台 path.resolve(rootReal, userPath)。
4. 对结果做 fs.realpath（如果存在）；符号链接、junction、reparse point 都跟到真实位置再判断。
5. 用 path.relative(rootReal, targetReal) 判断：结果不能是 ..、不能以 .. 加路径分隔符开头、不能是绝对路径。
6. 大小写：Windows 上 realpath 会给出规范大小写；不要只用字符串 startsWith 比较，必须用 path.relative。
7. 路径本身是根目录时允许（tree 用），但 read 根目录要拒绝并提示「这是一个目录」。

测试必须覆盖：../、.. 加反斜杠、绝对路径、盘符、UNC、符号链接指向根外、junction 指向根外、根内链接指向根内（允许）、大小写不同的根、尾部空格/点（Windows 会归一化）。

### 3. 永远拒绝的区域

即使主人把根配到了这些地方，也要硬拒绝：

- ~/.dsh-perch 整个目录（身份、配置、状态、事件、日记、渠道登录态）。
- ~/.dsh 整个目录（宿主配置、会话、凭据）。
- 任何根本身就是用户主目录、盘符根、C:\Windows、Program Files 这类系统目录。

这条是「配置错误也不开门」的兜底，不是靠主人记得不要填。

### 4. 默认不读的东西

- .git/：对象库又大又可能含历史凭据；看源码不需要。
- node_modules/、dist/、build/、.next/、coverage/、vendor/：太大，且不是项目自己的代码。
- .env、.env.*、*.pem、*.key、*.p12、*.jks、id_rsa*、id_ed25519*、cookies*、*.log（日志可能含令牌）。
- 二进制：先看前 8KB 是否有 NUL；再按常见扩展名拒绝（图片、压缩包、可执行文件、PDF、字体、数据库）。
- 超大文件：maxFileBytes 默认 256KB；超过就拒绝，告诉她「这个文件太大，先别整份读」。
- 单次输出：maxLines 默认 400，总字节 32KB；超过就截断并标 truncated。

这些默认值要能在配置里调，但硬拒绝区域不能调。

### 5. 只读，且不碰子进程

- 只用 node:fs 的读操作：readdir、stat、realpath、open + read。
- 不 writeFile、不 unlink、不 rename、不 mkdir、不 chmod。
- 不 child_process、不 eval、不 new Function、不动态 import() 用户给的路径。
- 不发网络请求。想读 GitHub 就用 web_fetch，两条线分开。
- 不把文件内容写进任何缓存文件；进程内可以缓存目录树，但要有上限，且不跨根混用。

### 6. 不自己加根

她不能通过工具参数新增根、改根、临时授权某个路径。根只能由主人在设置页改。工具参数里的 root 只能选已配置的别名，选不中就是拒绝。

## 七、怎么接进主包（工程上最容易踩的一节）

### 现状

- 主包 lib/index.js 在 apply 的 boot 里逐个 ctx.tools.register()。
- lib/restrict.js 的 FISH_TOOLS 是静态 10 项；HER_TOOLS 等于 FISH_TOOLS 加 read_image。
- ctx.tools.restrict() 只能减不能加，而且名字不存在会抛错。
- 所以：可选子包的新工具不能直接塞进静态 FISH_TOOLS。没装子包时，restrict 会因为找不到这个名字而失败。

### 建议：主包常驻一个薄工具，子包提供引擎

- 主包始终注册 project_look（薄包装，几十行）：校验配置、选根、把请求转给子包。
- 子包 dsh-perch-peek 提供真正的 tree / read / search 实现。
- 没装子包：project_look 仍然存在，但 execute 返回「看项目的组件没装，先装 dsh-perch-peek」。不读任何文件。
- 装了但没配置根：返回「还没告诉我能看哪个项目」。
- FISH_TOOLS 加 project_look，变成 11 项；selfcheck 的期望清单同步加一项。

这样工具名稳定，restrict 不会因为可选安装而抖，自检也简单。代价是没装子包时工具面多一个「暂时用不了」的工具；比起让 restrict 在缺名字时抛错，这个代价小。

### 备选：动态名单

如果一定要「没装就完全不出现」，就得让 HER_TOOLS 在 agent/created 时按实际注册情况算：project_look 在不在、根配没配。这样 FISH_TOOLS 不再是唯一真相，selfcheck 也要区分「必需」和「可选」。复杂度更高，不建议第一版走这条。

### 子包怎么加载

照 lib/channels/sub.js 的路子，但不要塞进渠道层：

- 新建 lib/peek/sub.js（或把 lib/channels/sub.js 通用化），候选：
  - dsh-perch-peek
  - ../../packages/dsh-perch-peek/index.js
- 只缓存成功；只有 ERR_MODULE_NOT_FOUND 才继续试下一个；其他错误要抛出来，不能静默当成「没装」。
- 加载失败只降级 project_look，不拖垮主包。

## 八、设置页怎么放

不新增页签。放在现有的「插件」页，工具面卡片下面，加一块「只读看项目」：

- 开关：peek.enabled，默认关。
- 根目录列表：别名 + 路径，可增删；保存时校验目录存在、不是硬拒绝区域。
- 每项旁边一句：「她只能读这个目录里的文本文件，不能写、不能执行、不能自己加目录。」
- 高级项（可折叠）：单文件上限、单次行数、是否允许搜索。
- 不出现「她喜欢看什么项目」这种人格化描述；这是环境权限，不是偏好。

文案要守现有守门测试：不出现男字旁的第三人称、不出现已禁用的门数说法、不写死名字。

## 九、读过项目要不要留痕

建议：不写事件流，不写 looked:。

理由：

- looked: 是「看过就是永久判决」的账，属于 B 站/抖音那种材料层。读一个源码文件不是「看过一个作品」，不该用同一本账。
- 写进 events.jsonl 会变成她的记忆素材，可能被召回；她只是查了一个函数，不该自动变成「经历」。
- 如果她自己觉得这件事重要，她会用 growth_commit 写一句判断；那才是记忆。

可以只在插件日志里留一行：[peek] alias=... path=... what=read ok=true，不写文件内容。日志是给主人排错的，不进她的提示词。

这一条可以商量：如果你希望「今天翻过哪些项目」能在今天页看到，可以另做一条只读的审计流水，但不要混进 events.jsonl。

## 十、测试清单

### 单元测试（不依赖真宿主）

1. 根未配置 / enabled:false：任何调用都拒绝，且不读文件。
2. tree：列出根、深度 1/2、忽略目录不出现、条目上限、排序稳定。
3. read：读一个文本文件、行号正确、from/lines 正确、超过 maxLines 标 truncated。
4. 路径攻击：../、.. 加反斜杠、绝对路径、盘符、UNC、\\?\、NUL、URL 编码的 %00 全部拒绝。
5. 符号链接：根内链接指向根内 → 允许；指向根外 → 拒绝；junction 同理。
6. 硬拒绝区域：就算把根配到 ~/.dsh-perch，也拒绝。
7. 敏感文件：.env、*.pem、id_rsa、cookies* 拒绝。
8. 二进制：NUL 文件、图片、压缩包拒绝。
9. 超大文件：超过 maxFileBytes 拒绝；不把整份读进内存。
10. 只读：源码里没有 writeFile / unlink / rename / child_process / eval。
11. search（如果 v1 就做）：字面量命中、行号正确、跳过二进制、命中上限、超时/文件数上限、不返回根外路径。
12. 返回里没有绝对路径。

### 集成测试

1. 不装子包：主包启动、全量测试、她的工具面不变；project_look 说「没装组件」。
2. 装了子包但 enabled:false：拒绝，不读。
3. 配置一个临时根：tree + read 成功，内容正确，路径是相对的。
4. 配置两个根：按别名选，不能串根。
5. restrict 挂上后 project_look 在 allow 里；selfcheck 不报缺工具。
6. 全量 node --test --test-isolation=none 仍只有 9 条已知环境红。

### 安全测试的临时目录

用 fs.mkdtemp 在系统临时目录建根，测试结束删掉。Windows 上符号链接可能需要权限；如果 fs.symlink 报 EPERM，测试跳过并注明「本机不支持符号链接测试」，不要为了让测试绿去放宽校验。

## 十二、待你定的问题

另开会话时，先回答这几个，剩下的实现细节可以边写边定：

1. 这个子包是不是「只读看项目/代码」？还是你心里是别的子包（比如 dsh-pet 的专用适配器、别的渠道）？如果是别的，这份文档的骨架可以复用，但能力模型要换。
2. 第一版要不要搜索？只做 tree + read 是否够看 dsh-pet？
3. 根目录怎么配？设置页填任意绝对路径，还是只允许仓库目录 / 某几个固定父目录？
4. 要不要允许读 node_modules？建议默认不读；但看某些库的源码时可能需要，可以做成每根单独开关。
5. 包名和工具名：dsh-perch-peek / project_look 可以吗？
6. 读过项目要不要留痕？建议不进 events.jsonl，只写插件日志；如果你要今天页能看到，另做审计流水。
7. 要不要支持 GitHub URL？建议不要；web_fetch 已经覆盖公开 URL，子包只读本地，边界更清楚。
8. 权限粒度：只到「根目录」够不够，还是需要每个根再配 include/exclude glob？建议 v1 只到根 + 默认忽略目录，别一上来做 glob。
