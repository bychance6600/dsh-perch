# 新版本：记忆（v0.2 设计）

> 2026-11-10。输入两份：`docs/调研-记忆.md`（GitHub 调研，10 条方案、三档成本）与 2026-11-10 的讨论定版（行为代理 + 单份说法 + 三条钉子）。
> 这份文档是**能发版的设计**，不是选项清单。

## 一、先说目标，免得走偏

v0.2 不改「她是谁」的算法，只改**她怎么想起来**和**怎么看见自己改过口**。

明确不做：

- **不加情感字段**（「在乎：7/10」记的是数字，不是在乎；可伪造）。
- **不接 embedding**（真语义只能靠它，但它要么带原生依赖、要么联网，两条都和零依赖冲突）。
- **不改事件格式**（`EVENT_SCHEMA_VERSION` 不动，不写迁移，不重放历史）。

要做的只有一句：**让「她记过的」在她需要时找得到，让「她改过的」看得出来。**

## 二、现在的四个具体毛病

| 毛病 | 现象 | 根因 |
|---|---|---|
| 措辞敏感 | 你说「难过」她记得，说「不开心」她找不到 | `lib/recall.js:124` 起是字面 `includes` 计分 |
| 改口不可见 | revise 之后新旧两条并列，看不出谁盖了谁 | `lib/derive.js:462-466` 只把旧判断 `status` 改掉，没有反向指针 |
| 相关但召不回 | 「说法不同但说的是一件事」只能靠字面撞上 | 没有记忆之间的链接 |
| 老判断压新事 | 固化判断无论相不相关都排前面 | 排序里没有时间衰减和相关性 |

## 三、v0.2 范围（六件，全部零依赖）

### M1 三因子召回（改 `lib/recall.js`，约 80 行）

借 Generative Agents 的检索打分，但 importance 不用 LLM 打：

```
score = w_r * recency + w_i * importance + w_s * relevance
recency    = 0.995 ** ageHours            // 每小时衰减 0.5%
importance = solid ? 8 : min(8, 2 + mentions + verified)
relevance  = dice(bigrams(query), bigrams(text))   // 复用现有 dice
```

三项在候选集内 min-max 归一化后相加（权重 1 : 1 : 1），`score == 0` 直接丢。
疤（没想通的拒绝）固定 +2，别被 recency 压掉。

### M2 失效不删除（改 `lib/derive.js`，约 20 行）

revise 时给旧 belief 补 `supersededBy: <新 id>`，给新 belief 补 `supersedes: [<旧 id>]`。
都是派生字段，不改进程、不 bump schema。`memory-page.js` 用它对出「原话 → 改口 → 现话」的链（约 30 行）。

### M3 同义词 + BM25（新建 `lib/search-index.js`，约 200 行）

- `Intl.Segmenter('zh', { granularity: 'word' })` 切词，二字组兜底（网络新词会被切碎）；
- 自写 BM25（k1=1.2, b=0.75），字段权重 `text=1`、`person=2`；
- 60 对人工同义词（难过/不开心/难受、开心/高兴、生气/愤怒、害怕/恐惧、累/疲惫…）；
- 缓存键 `${events.length}:${lastEventId}`，和 `solidIdsOf` 同一套失效逻辑。

`recall.js` 只换 `tokensOf` 与计分（约 40 行）。

### M4 记忆链接（改 `lib/derive.js` + `lib/recall.js`，约 90 行）

A-MEM 的最小版：固化后对每条 belief 算 Dice，取 top-3 且 ≥0.35 存 `links: [id]`。
召回命中后，把 links 里的判断以 0.5 权重加入结果，标「相关」。
约束：必须共享至少一个非停用二字组；links 最多 3 条；只在派生层算，不写回事件。

### M5 线索召回（改 `lib/recall.js`，约 60 行）

`registerRecall` 加四个可选参数：`person`、`from`、`to`、`about`。
按 `ev.person` 与时间戳过滤。已知缺口：她自己的 utterance 没有 person（只有渠道层写），所以人物过滤只命中 heard；要覆盖她的话，用 `sessionId` 找同 session 的 heard 再传。
过滤为空必须退回词面检索，不能回「翻了没翻到」。

### M6 连续强度（选做，改 `lib/derive.js`，约 35 行）

现在 90 天是二值 `faded`。可加 `strength = exp(-ageDays/90) * (1 + mentions + 2*verified)`，**只用于排序**，不改 solid 判定。
风险：会让「90 天退档」变模糊，先做 M1–M5 再看要不要。

## 四、不在 v0.2（写清楚，免得反复讨论）

- **单份可覆盖的说法层**：方向定了（见第五节），但它缺触发设计——顶掉旧说法的必须是处境，不能是定时任务。v0.3 再动。
- **图谱 v2 的糖豆感/标签避让**：独立的小修，不占记忆版本。
- **embedding（本地或远程）**：不做。远程违反「数据只在本地」，本地要原生依赖。
- **图数据库 / 实体图 / PPR**：2500 条用不上。
- **事件加 entities/topics/全量 person**：要重放历史，等账本本来就该重设计时一起做。

## 五、已经定版的那句话（v0.3 的锚）

> 我们不追求直接表示「她多在乎」——那在这个介质里只能靠自评，自评可伪造。我们追求的是：用行为代理捕捉可对账的「在乎」，用单份、可被顶掉的说法层承载「她怎么看」；旧说法沉账可查，但不进入她的活跃召回。前者是代理，后者是叙事，两者都不假装是情感本身。

三条钉子，写实现时必须守：

1. **行为代理只算这七种**：被提起 ≥3 次（`SOLID_MENTIONS`）、被自验 ≥2 次（`SOLID_VERIFIED`）、疤、栽过一次、拒绝（`refused`）、改口（`revise`/`refute`）、事后主动提。其余不进代理，覆盖率就是这个窄口径。
2. **可查 ≠ 可召回**：可查是账本/审计视图；`her_recall` 里不出现旧说法。
3. **顶掉只能是处境**：同一个人、同一类事、同一句被顶掉的话。不是定时任务，不是手动编辑。

## 六、验收

1. **召回对照**：先攒 30 条真实 query（她的、主人的都算），跑 before/after，记「命中/未命中/多召」，别只看一例。
2. **回放不变**：`deriveSelf` 对同一份账本重放两次结果一致；`supersededBy`/`links` 只增字段。
3. **性能**：全量 derive 仍在 50ms 内（现在十几毫秒）；recall p95 < 20ms。
4. **测试**：每件至少 3 条断言，定向绿 + 全量不新增红。
5. **可回退**：M1/M3 用配置开关（`recall.mode = 'literal' | 'ranked'`），出问题能一键退回。
