# v1 与 v0.2 冲突清单

审计对象：`docs/新版本-记忆.md`（v0.2，讨论稿）对照当前代码（v1）。只列核过的行号；拿不准的标「未核」。v0.2 文档自身第八节已列 4 条，这里拆成可回答的取舍，并补上它没列的。

## 一、一句话结论

v0.2 开做前必须先定四件，按「不定就返工」排序：**①M1 归一化在候选只有一条时记几分**——记 0 则 `her_recall` 最常见的单命中直接返空，召回层与 3 处断言一起重做；**②印象还是一条还是按渠道群分面、超 150 先丢哪段**——牵动 `people.js`、`impression.js`、`router.js`、`client.js` 四处；**③status 与 supersededBy 谁是唯一来源、confirmed 算不算改口**——牵动 `derive.js`、`observe.js`、`memory-page.js` 与旧账本；**④今天页与记忆页的改口/连线数字按事件还是按节点**——两处现在是两套算法，M2/M4 一上就会对不上。

## 三、按主题分组的小结

- **召回层**：真正的返工点在「候选集退化」和「数据从哪来」——M1 要的 mentions/verified/scar 现在都不在 `searchEvents` 手里；M3 又承诺只动 `recall.js`，但 `matchPeople`、`tokensOf`、`weigh` 都会被牵动。缓存已经有单 slot 的 `solidCache`，再加 links/index 三个键不同步，是第二处返工源。
- **判断层**：`status` 是三值契约，`supersededBy` 却想当第二套真相；`confirmed` 被写成 `refined`，`refined++` 又不认它，计数和链会各错一次。M2 说「只补关系」，实际还要补 refined 的变更记录与边。
- **印象层**：单条 150 字、四段、6 句重写、last 覆盖，四个决定绑在一条字符串上；`people.json` 的 normalize 还留着 4 条 said（与 `SAID_MAX=3` 不一致）。分面不是只改 `composeImpression`，写入口在渠道层、消费口在 prompt 与 `her_recall`。
- **展示层**：今天页按事件、记忆页按节点，改口数字现在就对不上；页面还自算了一套 0.34/900 的相近边（在截断 140 字上算），M4 的 links 是第四套相似度。加上 `stats.hard` 复用 tension 数，任何「连线数」都会再分叉。
- **数据层**：`supersededBy`/`links` 只能是派生字段——`validateEvent` 的白名单会把它们静默丢掉，所以「写回账本」等于改 schema。旧账本里早期改口没有 refs，链天然缺一段；v0.2 又说不重放历史，需要明确接受这个缺口。
- **工具面**：`her_recall` 的说明、参数、`kind` 列表都要改；M5 的 person 前提与代码不符（渠道 utterance 带 person），且 `u_` 前缀归一不在 recall 里。`her_diary` 只写 `meta diary:`、`her_note` 存独立 json，二者不受召回影响；`her_leave` 写的是 `utterance`（`lib/letter.js:131-146`），会进召回，不能划到范围外。

## 四、明确不受影响的部分

- **四道闸**（`lib/socialgate.js`）与 `influence` 定格规则：只从事件流算，v0.2 不碰。
- **桌宠协议**（`lib/pet/*`、`pet.json` 动作表、醒睡判定）：与记忆派生无交集。
- **渠道层除印象外的部分**：登录/桥/可见性/防串话不受影响；但印象由 `router.js:640` 写、`router.js:153,663` 读，**不能把整个渠道层划到范围外**。
- **事件写入格式**：只要坚持派生不落盘，`EVENT_SCHEMA_VERSION` 与迁移都不用动（第 29 条是唯一分叉）。
- **日记与纸条**：`her_diary` 写 `diary/*.md`、`her_note` 写 notes.json，都不进事件流；`her_leave` 留的话是 `utterance`，会进召回（M1/M3 会影响它的排序），不能算范围外。
